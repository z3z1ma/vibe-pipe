# Dead code and unused module pruning

# Dead code and unused module pruning

Objective alignment:
Reduce maintenance surface area by removing code paths that are unused in the library, tests, or examples.

Scope:
- `src/vibe_piper/` modules and exports
- References in `tests/`, `examples/`, and docs that mention removed modules

Non-goals:
- No feature additions or API redesign
- No performance refactors beyond removing unused code

Plan:
1. Build a candidate list of unused modules/functions by searching for imports/references across `src/`, `tests/`, `examples/`, and `docs/`.
2. Confirm public API exposure via `src/vibe_piper/__init__.py` and docs references.
3. Remove unused modules or functions; update imports, exports, and docs accordingly.
4. Update or delete any tests that only cover removed code.
5. Run formatting, lint, typecheck, and a fast test suite.

Acceptance criteria:
- No unused module remains that is unreferenced by `src/`, `tests/`, `examples/`, or docs.
- Public API exports reflect the remaining modules.
- Tests and docs do not reference removed code.

Verification:
- `uv run ruff format src tests`
- `uv run ruff check src tests`
- `uv run mypy src`
- `uv run pytest -m \"not integration\"`

Risks/edge cases:
- Some modules may be used via dynamic imports; verify with docs/examples before removal.
- Removing a module may break external users; ensure it is not part of the documented public API.

## Acceptance Criteria

Unused modules removed; public API and docs updated; ruff/mypy/pytest pass
