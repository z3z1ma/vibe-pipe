# Docs pruning + reindex

## Objective alignment
Documentation must be coherent and aligned to the final API so users can trust the docs.

## Scope
- Audit `docs/` and `docs/source/` for stale or obsolete content.
- Remove or archive investigation/planning docs not meant for users.
- Update `docs/source/index.rst` to include only maintained docs.
- Fix CLI command names and install extras to match `pyproject.toml`.

## Non-goals
- Creating brand-new feature docs beyond what exists.
- Major reorganization of doc tooling (Sphinx stays).

## Plan
1. Inventory docs and categorize: core, optional, obsolete.
2. Remove or move obsolete docs (e.g., investigation/missing abstraction notes) out of user-facing paths.
3. Update remaining docs to reflect current modules and API names.
4. Align docs with any feature removals (web/dashboard, etc.).
5. Build Sphinx docs to ensure no broken references.

## Acceptance criteria
- `docs/source/index.rst` includes only existing, maintained docs.
- No docs reference removed modules or the `vibe-piper` CLI name.
- Sphinx build succeeds.

## Verification
- `cd docs && uv run sphinx-build -b html source build/html`

## Risks / edge cases
- Removing docs could break links in README or other docs; ensure links updated.

## Dependencies
- Depends on public API pruning and web/dashboard removal tickets.


## Acceptance Criteria

Docs reflect current APIs; stale docs removed; Sphinx index matches maintained docs
