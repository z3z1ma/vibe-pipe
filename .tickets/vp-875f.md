# Sprint prep: Examples Revitalization

Objective:
We are creating the most robust python based declarative data pipeline, integration, quality, transformation, activation library ever created. Our zen is simplicity and maximizing expressivity and composability. Now we need to focus on clearing out our examples directory and rebuilding it from the ground up with fully functional interesting examples that showcase the value of the library and act as adhoc UAT or sandbox as we expand capabilities.

## Sprint Brief

- Objective restatement: Rebuild the examples directory into a curated set of runnable, interesting pipelines that exercise current APIs and serve as living UAT.
- Sprint focus (2 to 5 words): Runnable examples rebuild
- Why this sprint focus is the best next step: The repo currently has sprawling, inconsistent examples and generated artifacts. A clean, runnable set will drive adoption, validate APIs, and provide reliable sandboxes for future capability work.
- Current state:
  - Existing tickets that matter: Only vp-875f was open; sprint tickets created under this prep ticket.
  - Codebase state that matters: examples/ contains api_ingestion, etl_pipeline, drift_detection_example.py, transformation_example.py, demo_pipeline configs, and sample_pipeline docs outputs; root README examples list references old items; git status only shows untracked .venv.
- Risks and unknowns (and how we will resolve them):
  - Example code may not match current APIs or optional extras. Resolve by aligning imports with src/vibe_piper and adding uv run smoke tests.
  - Optional dependencies (postgres, files) may cause friction. Resolve by documenting uv pip install -e ".[files]" or ".[postgres]" and adding dry run paths where possible.
  - Removing old example directories could break doc references. Resolve by updating README links in the cleanup ticket.
