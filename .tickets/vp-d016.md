# Docs + README alignment for canonical APIs

## Objective alignment
The project's UX is only as good as its documentation. Current docs reference APIs and workflows that don't exist or don't work. Aligning docs with the canonical AssetGraph workflow improves cohesion and reduces confusion.

## Scope
- Update README examples that use `build_pipeline(load_asset)` to match real APIs (PipelineBuilder or new helper from vp-3fcc).
- Update `docs/sql_assets.md` with the execution contract (connector requirement, dependency mapping).
- Update docs that imply `@asset` alone can build a graph without explicit dependencies.
- Add a concise "canonical pattern" section reflecting the core abstraction contract.

## Non-goals
- No changes to core code beyond docs (code changes are covered in other tickets).
- No new user guides outside Phase 3 scope.

## Implementation plan
1. Search README.md for `build_pipeline(` usage and update to canonical API.
2. Update `docs/execution_layering.md` and related guides to show explicit dependency declaration (`depends_on`) or builder usage.
3. Update `docs/sql_assets.md` to document connector/config requirements and template dependency mapping.
4. Add a short "When to use AssetGraph vs Pipeline" cross-link to CORE_ABSTRACTION_CONTRACT.md.

## Acceptance criteria
- README examples are executable given the current APIs (or after vp-3fcc/vp-92d4 changes).
- SQL asset docs explain required configuration and dependency substitution.
- No lingering references to unsupported `build_pipeline(load_asset)` behavior.
